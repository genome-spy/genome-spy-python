# Devlog archive: 2026-06-24 to 2026-06-25

## 2026-06-25 - Schema generation and notebook debugging
- Replaced the toy dataset direction with Altair dataset usage in the
  Altair-style penguins notebook and removed the first-party dataset package.
- Added spec debugging helpers so `chart.spec`, `chart.to_json()`, and
  notebook spec display produce valid, pretty-printed JSON.
- Built GenomeSpy core's real `packages/core/dist/schema.json` with npm and
  generated the first `genome_spy.schema` package from it.
- Added low-level generated schema wrappers, packaged the schema JSON, and
  documented the current codegen mapping in `plans/`.
- Added a notebook cell that writes the penguins chart spec to
  `notebooks/palmer_penguins_genomespy_spec.json`.
- Recreated `.agents` skills for commit and devlog workflows with
  Codex-compatible YAML frontmatter; `.agents/` remains gitignored.
- Validated with `uv run ruff check src tests tools`, `uv run mypy src/`,
  `uv run pytest tests/ -q`, `uv build`, and notebook execution via
  `uv run jupyter nbconvert`.

## 2026-06-25 - Altair-style codegen workflow decision
- Confirmed from the Altair repo that generated schema Python files are tracked
  in git and shipped with the package, not generated during package
  installation.
- Documented that `genome-spy-python` should follow the same workflow:
  maintainers regenerate from the pinned `@genome-spy/core` npm package,
  commit `src/genome_spy/schema/`, and eventually let CI fail if regeneration
  changes tracked files.
- Clarified that npm is only a developer prerequisite for code generation;
  installed package users should not need npm or network access for schema
  wrappers.

## 2026-06-25 - GenomeSpy stacked bar notebook
