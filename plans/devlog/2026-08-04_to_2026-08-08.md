  check of all 15 dataset-backed gallery examples (43 Arrow references) passed.

## 2026-08-07 - Issue 1 automatic Arrow IPC transport

- Added one private render-preparation traversal that replaces supported view
  `data` table objects with content-addressed Arrow sources while retaining
  unchanged JSON behavior for `to_dict()`, `to_json()`, saved specs, and record
  lists. The per-render object memo prevents duplicate encoding inside composed
  charts without a stale persistent cache.
- Added lazy Polars, pandas, PyArrow `Table`, and PyArrow `RecordBatch` IPC
  writers. PyArrow is an optional `arrow` extra and an explicit docs/dev test
  dependency; pandas deliberately falls back to JSON when it is absent.
- Replaced dataframe record-based type inference with table dtype metadata so
  preparing supported dataframe charts does not materialize rows.
- Removed the experimental public manual `arrow_data` argument. Widgets now
  receive prepared buffers automatically, preserve `DataView` offsets, create
  one Blob URL per buffer, and revoke URLs on settled, stale, failed, and
  disposed renders. The ESM is packaged and tested with Node's built-in runner.
- Gallery generation now consumes prepared specs, writes verified
  content-addressed `.arrow` assets one at a time, rewrites only private Arrow
  tokens, passes generated spec URLs directly to GenomeSpy for correct relative
  resolution, and cleans only stale owned assets after success.
- Validation passed: full Python tests, Ruff, MyPy, Node widget tests, strict
  Sphinx HTML build, and a wheel inspection confirming the ESM asset ships.
- The deterministic local benchmark confirms the expected trade-off: Arrow has
  higher fixed overhead for 8 rows (1,039 bytes versus 462 bytes) but is smaller
  and faster to encode for the tested 1,000-row (32,783 versus 60,097 bytes)
  and 10,000-row (320,783 versus 610,846 bytes) Polars tables. This supports
  the policy of retaining ordinary Python record lists as JSON while using
  Arrow for supported dataframe objects.
